# Contract alignment (design ↔ API ↔ backend ↔ frontend)

Date: 2026-11-19. Scope: every screen ↔ route ↔ endpoint, every notification type ↔ channel ↔ payload field, and
every shared enum across [`design/`](design/), [`api/`](api/), [`backend/`](backend/) and [`frontend/`](frontend/).
[`PRD.md`](PRD.md) decides scope; nothing below adds scope beyond it. P1/P2 items are given a contract shape or
explicitly deferred.

Validation after the first pass: `openapi.yaml` passed `openapi-spec-validator` (50 paths); `schema.sql` applied to an
empty PostgreSQL 16 database; both rule examples validated; prototype group A re-rendered after #20.

**Second pass, same day — founder decisions of 2026-11-19** ([PRD.md](PRD.md) top section; rows #42–#63 below).
Validation after these edits: `openapi.yaml` passes `openapi-spec-validator` 0.9.0 (OpenAPI 3.1, **36 paths, 42
operations**); `schema.sql` loads into an empty local PostgreSQL 16 with `ON_ERROR_STOP` (35 tables) and the
`locale_keys_ok` CHECK rejects a `LocalizedText` without `en`; `rule.schema.json` passes the Draft 2020-12 meta-schema
and both `backend/examples/*.rule.json` validate against it. `docs/design/` was edited in parallel by the design pass
(its [CHANGES-2026-11-19.md](design/CHANGES-2026-11-19.md)); this pass did not edit it and lists below what design
should still pick up.

| Topic | Canonical value |
